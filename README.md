# AccountDomino

비밀번호 재사용과 MFA(2차 인증) 설정에 따라 크리덴셜 스터핑 피해가 어떻게 번지는지 보여주는 **로컬 전용 교육용 시뮬레이터**입니다.
한 서비스에서 유출된 아이디·비밀번호 한 쌍을 다른 서비스들에 각각 따로 시도해, 비밀번호 분리와 MFA가 접근을 어디서 막는지 설정 변경 전후로 비교합니다.

> ⚠️ 모든 계정·비밀번호는 가상 데이터입니다. 앱은 `127.0.0.1`의 모의 인증 서버에만 요청하며, 실제 외부 서비스나 실제 계정에는 절대 요청하지 않습니다.
> (`accountdomino/client.py`는 `localhost`/`127.0.0.1` 외의 주소를 거부합니다.)

## 구성

| 구성 요소 | 역할 |
|---|---|
| Streamlit (`app.py`) | 사용자 화면: 소개 → 시나리오 선택 → 계정 설정 → 유출 출처 선택 → 시뮬레이션 (테마: `.streamlit/config.toml`) |
| FastAPI (`accountdomino/api.py`) | 모의 인증 서버. 하나의 서버에서 `service_id`로 가상 서비스 20개(메일·쇼핑·커뮤니티·학교·게임·클라우드 등)를 구분 |
| SQLite (`data/accountdomino.db`) | 계정(해시), 실행 기록, 로그인 로그 저장 |

```
accountdomino/
  config.py      서비스 카탈로그(20개), 계정 수 범위(4~20, 기본 12), 결과 상수, DB/API 경로
  security.py    PBKDF2-HMAC-SHA256 + 계정별 salt 해시
  db.py          스키마
  auth.py        핵심 인증 로직(판정·로그 기록)
  scenarios.py   비밀번호 그룹, 기본 시나리오 3개(계정 수에 맞춰 규칙으로 생성)
  simulation.py  유출 자격증명, 검사 대상, 설정 대조 판정, 결과 집계, 애니메이션 데이터
  animation.py   시뮬레이션 컴포넌트 등록(st.components.v2)
  static/simulation.{html,css,js}  시뮬레이션 창(외부 리소스 없음)
  api.py         FastAPI 앱
  client.py      localhost 전용 API 클라이언트
app.py           Streamlit 화면
scripts/init_db.py  DB 초기화 + 기본 시나리오 적재
tests/           핵심 인증 로직·API·시나리오·애니메이션 데이터 테스트
```

## 실행 방법

Python 3.11 이상, Streamlit 1.64 이상(양방향 컴포넌트 `st.components.v2` 사용)이 필요합니다.

```powershell
python -m venv .venv
.venv\Scripts\activate            # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt

python scripts/init_db.py         # DB 초기화 (옵션: --scenario s1|s2|s3, --count 4~20)

# 터미널 1: 모의 인증 서버
uvicorn accountdomino.api:app --host 127.0.0.1 --port 8000

# 터미널 2: 사용자 화면 (http://localhost:8501)
streamlit run app.py
```

API 문서는 서버 실행 후 http://127.0.0.1:8000/docs 에서 확인할 수 있습니다.

## 사용 흐름

한 단계를 한 페이지로 보여 줍니다(설정 3단계). **이전**으로 돌아가도 입력값(시나리오, 계정 수, 표 편집값, 비밀번호 그룹 값, 유출 출처)은 그대로 유지됩니다.

1. **시작 화면**: 왼쪽에 `크리덴셜 스터핑이란?` 설명과 **시뮬레이션 시작하기 →** 버튼, 오른쪽에 중앙 유출 정보와 주변 서비스를 잇는 정적 네트워크 그림(공격 흐름 예시, 애니메이션 없음). 좁은 화면에서는 설명 아래로 그림이 내려갑니다.
2. **시나리오 선택**: 시나리오 드롭다운(일부 계정에 MFA 적용 / 서비스별 비밀번호 분리 / 전체 계정에 MFA 적용)과 가상 서비스 계정 수(4~20개, 기본 12개). 드롭다운 아래 한 줄로 바뀌는 조건을 실제 설정에서 계산해 보여 줍니다(예: `변경 후: 메일·학교·클라우드 MFA ON`).
   - 시나리오를 바꾸면 현재 계정 수에 맞춰 설정과 유출 출처를 기본값으로 **새로 채웁니다**.
   - 계정 수를 바꾸면 남는 계정의 입력값은 그대로 두고, 늘어난 계정만 기본값으로 채웁니다(줄이면 뒤쪽 계정부터 뺍니다).
3. **계정 설정**: 변경 전·후를 **각각의 표**로 좌우에 두고(열: 서비스 / 아이디 / 그룹 / MFA), 두 표를 **하나의 스크롤 영역**에 넣어 함께 넘겨 봅니다. 쪽 넘김이 없고 같은 서비스는 양쪽 같은 줄에 있어 전후 차이가 바로 보입니다. 열 머리글은 표 바로 위에 붙어 스크롤해도 남고, 전후 제목과 **비밀번호 편집** 버튼(오른쪽 끝이 표 끝에 맞춰져 있습니다)은 목록 위에 고정됩니다. 목록은 화면 안에 들어가도록 높이를 잡아 세로 스크롤바가 표 옆 하나만 생깁니다.
   - 각 표 제목 옆의 **비밀번호 편집** 버튼을 누르면 작은 창이 열립니다. 창에서 그룹 `A`~`D` 를 고르고 그 그룹의 비밀번호를 입력하며, 값은 가려서 표시하고 눈 아이콘으로 잠깐 확인할 수 있습니다. 안내는 `실제 사용 중인 비밀번호 대신 실습용 값을 입력하세요.` 이고, 그 값을 쓰는 계정 수와 서비스명을 함께 보여 줍니다.
   - 그룹을 바꿔도 입력하던 값은 창 안에서 유지되며, **적용**을 눌러야 저장됩니다. **취소**·`X`·`Esc`·바깥 클릭은 입력을 폐기합니다. 창을 열고 닫아도 계정 표에 편집하던 내용은 그대로 남습니다.
   - 변경 전·후 값은 서로 독립이라 **변경 후를 고쳐도 변경 전 결과는 달라지지 않습니다**. 계정의 그룹 배정은 바뀌지 않고, 다른 그룹에 같은 값이 있으면 한 줄로 알려 줍니다. 판정은 그룹 이름이 아니라 **입력한 값**으로 이루어집니다. `고유`는 입력 없이 서비스마다 다른 값이 자동으로 쓰입니다.
4. **유출 출처 선택**: `로그인 정보가 유출된 계정`을 드롭다운으로 고르면 `커뮤니티 · 아이디 student01 · 비밀번호 A`, `다른 11개 서비스에 시도`처럼 간결하게 표시합니다. **시뮬레이션 시작**을 누르면 실행 당시 설정을 복사해 두고 두 설정에서 모의 로그인합니다.
5. **시뮬레이션**(계정 보안 시뮬레이션): 앱 안의 큰 창으로 열립니다.
   - **보기 전환**: `결과 비교` · `과정 보기: 변경 전` · `과정 보기: 변경 후`. 창을 열면 **변경 전 과정이 먼저 재생**되고, `결과 비교`는 잠겨 있습니다. 전후를 자동으로 이어 재생하지 않으며, 변경 후 과정도 직접 골라 봅니다.
   - **결과 비교는 언제든 열 수 있습니다**: 전후 결과는 실행할 때 이미 모두 받아 두므로 재생이 끝나지 않아도 바로 볼 수 있고, 들어가면 진행 중이던 재생은 멈춥니다. 과정 보기는 단계를 하나씩 공개하지만 결과 비교는 처음부터 최종 결과만 보여 줍니다.
   - **결과 비교**: 애니메이션 없는 정적 표로, 왼쪽은 변경 전 최종 결과, 오른쪽은 변경 후 최종 결과를 **같은 서비스 = 같은 행**으로 나란히 둡니다. 각 칸에 상태(아이콘+색)와 짧은 이유가 있고, 변경 후 칸에는 바뀐 설정 태그(`MFA OFF → ON` 등)가 붙습니다. 위에는 `두 설정 모두 … 같은 유출 정보로 시도했습니다` 안내, 아래에는 전후 침해·차단·확인 필요 수와 비교 문장이 있습니다. 각 열의 `과정 보기 →` 로 해당 프로필의 과정 애니메이션으로 넘어갑니다. 계정이 많으면 세로로 스크롤하되 좌우 행은 계속 같은 줄에 있습니다.
   - **과정 보기의 배치**: 넓은 화면(약 1450px 이상)에서는 좌우를 **2열씩(총 4열)** 쌓아 한 번에 더 많은 계정을 봅니다. 바깥 열은 카드 반 칸만큼 엇갈려 두어, 바깥 열로 가는 연결선이 안쪽 카드 사이 틈으로 지나가고 카드를 가로지르지 않습니다. 좁은 화면에서는 자동으로 좌우 1열씩으로 돌아갑니다. 중앙에 유출 정보(출처·아이디·비밀번호 그룹)를 두고 서비스를 좌우로 균형 있게 배치합니다. 모든 서비스는 중앙에서 직접 연결되며, 다른 서비스를 거쳐 전파되는 것처럼 보이지 않습니다. 연결선은 카드·글자를 통과하지 않습니다.
   - **과정 보기**: 각 카드에 실행 당시 설정이 한 줄로(`student01 · 그룹 A · MFA 꺼짐`) 보이고, 그 아래 **아이디 / 비밀번호 / 추가 인증** 세 줄의 검사 기록(`일치`·`불일치`·`사용 안 함`·`미완료`·`진행하지 않음`)과 **최종 결과 한 줄**(`계정 침해`·`로그인 시도 차단`·`확인 필요`)이 따로 있습니다. 사유를 길게 반복하지 않고, 자세한 사유·해시·salt 는 상세창에 둡니다. 검사 줄은 `대기 → 확인 중 → 판정` 순서로 하나씩 공개되며, 지금 보는 줄만 강조하고 아직 오지 않은 판정은 숨깁니다. 한 번 나온 기록은 재생이 끝난 뒤에도 그대로 남습니다.
   - **1배속 한 번 재생 약 19초**입니다: 설정 확인 3초 → 토큰 이동 2초 → 아이디 4초 → 비밀번호 5초 → 추가 인증 5초. 각 구간의 뒤쪽 절반은 판정을 읽는 시간입니다. 계정 수가 늘어도 시간축은 같고 모든 카드가 동시에 진행하며, 먼저 차단된 카드는 기록을 유지한 채 나머지가 계속 진행합니다.
   - 변경 후 카드에는 바뀐 설정 태그가 붙습니다. 그룹 이름이 그대로여도 **전후 실제 비밀번호 값이 달라지면 `비밀번호 값 변경`** 으로 알려 줍니다(값 비교는 실행할 때 하고, 저장에는 표시용 메타데이터만 남깁니다).
   - 상태는 색·아이콘·문구를 함께 씁니다: 진행 중(파랑 점), **로그인 시도 차단(초록 방패)**, 계정 침해(빨강 + 열린 자물쇠), 확인 필요(노랑 경고). 비밀번호 불일치는 **보호에 성공한 것**이므로 빨간 오류가 아니라 초록 방패로 보여 줍니다. 계정 침해는 비인가 로그인이라 초록 성공색을 쓰지 않고, 강한 색으로 카드를 채우기보다 테두리·아이콘·문구에 적용합니다.
   - **컨트롤**: 배속(0.25×/0.5×/1×/1.5×/2×, 기본 1×에서 한 번 재생 약 10초), 재생·일시정지·처음부터, 그리고 일시정지 중 쓰는 **다음 단계**. 배속은 화면 재생 시간에만 영향을 주고 인증 API 를 다시 부르지 않으며, 배속을 바꿔도 진행 위치를 유지합니다. 재생이 끝나도 최종 상태를 유지합니다(자동 반복 없음).
   - **상세창**: 결과 표의 칸이나 과정 보기의 카드를 누르면 유출 정보와 대상 계정 설정 비교, 결과와 설명, 그리고 **저장된 비밀번호 해시**(축약 → `전체 해시 보기`로 펼침), `salt`, 서버가 실제 수행한 검증 결과가 함께 뜹니다. 같은 비밀번호라도 계정별 salt 때문에 저장 해시가 다르므로, 해시 문자열만 보고 서비스끼리 비교해 판단하지 않도록 서버 검증 결과를 같이 보여 줍니다. 해시는 상세창에만 두어 카드가 길어지지 않습니다. 상세창을 열면 재생이 멈추고 닫으면 이전 상태로 돌아가며, Esc 는 상세창만 닫습니다.
   - 아이콘 버튼에는 툴팁·접근성 이름이 있고, `prefers-reduced-motion` 에서는 토큰 이동을 생략하되 단계와 결과는 그대로 확인할 수 있습니다.
   - **종료**: 우측 상단 X 또는 Esc → 재생을 잠시 멈추고 `시뮬레이션을 종료하겠습니까?` 확인창(계속 보기 / 종료). **계속 보기**는 확인창을 열기 전의 재생·일시정지 상태로 돌아가고, **종료**는 애니메이션을 정리한 뒤 입력값이 그대로인 유출 출처 화면으로 돌아갑니다. 확인창이 떠 있는 동안 Esc는 취소로만 동작합니다.

상세 결과표와 로그는 사용자 화면에 보이지 않지만, 검증용으로 DB(`runs`, `login_logs`)에 계속 기록되며 API `GET /logs`, `GET /runs/{run_id}/logs`로 확인할 수 있습니다.

결과를 오해 없이 보여주기 위한 규칙:

- **결과도 이유도 모의 인증 서버가 실제 수행한 단계 기록에서** 나옵니다. 화면이 설정만 보고 결과를 따로 만들어 내지 않습니다(`/login` 응답의 `steps`·`verified`·해시를 그대로 사용).
- 네트워크 오류나 알 수 없는 응답은 `확인 필요`로 표시하며, 성공·차단 집계에서 제외합니다.
- `유출`은 출처 계정에만 씁니다. 대상 서비스의 로그인 결과를 `비밀번호 유출`이나 `해시 크랙 성공`으로 표시하지 않으며, `완전히 안전`·`해킹 불가능` 같은 보장 표현도 쓰지 않습니다.
- 애니메이션은 **시작 시점의 설정·결과 스냅샷**만 사용하며, 실행마다 새로 그려 이전 실행 결과와 섞이지 않습니다.
- 유출 출처 계정은 검사 대상이 아니며, 변경 후 설정에서 출처 계정이 어떻게 바뀌었는지는 **설정 비교**로만 안내합니다.

### 판정 규칙

| 조건 | 결과 |
|---|---|
| 아이디가 없거나 비밀번호 해시가 다름 | `비밀번호 불일치` (계정 존재 여부는 노출하지 않음) |
| 비밀번호는 맞지만 MFA 적용 | `MFA 차단` (로그인 시도자는 추가 인증 수단이 없다고 가정) |
| 비밀번호가 맞고 MFA 미적용 | `접근 성공` |

차단 계정 수 = `비밀번호 불일치` + `MFA 차단`. 유출 정보는 **변경 전** 설정의 출처 계정에서 한 번만 만들고, 변경 전·후 모두 같은 정보로 시도합니다.

API 내부 결과값은 그대로 두고, 화면에는 피해·보호가 드러나는 라벨로 바꿔 보여 줍니다.

| 판정 | 화면 표시 | 짧은 이유 | 색·아이콘 |
|---|---|---|---|
| 비인가 로그인 성공 | `계정 침해` | 유출된 로그인 정보로 로그인 성공 | 빨강 · 열린 자물쇠 |
| 비밀번호 불일치 | `로그인 시도 차단` | 유출 비밀번호와 다름 | 초록 · 방패 |
| MFA 차단 | `로그인 시도 차단` | 추가 인증에서 차단 | 초록 · 방패 |
| 아이디 불일치 | `로그인 시도 차단` | 아이디 불일치 | 초록 · 방패 |
| 요청 오류 | `확인 필요` | 요청 오류 | 노랑 · 경고 |
| 알 수 없는 결과 | `확인 필요` | 설정과 결과 불일치 | 노랑 · 경고 |

### 비밀번호 그룹

- 같은 그룹이면 같은 비밀번호를 사용합니다. `A`~`D`는 그룹별 실습용 비밀번호이며, 기본 예시값(예: 그룹 A = `Domino-A!2024`)이 채워진 채로 **계정 설정 화면의 ‘비밀번호 편집’ 미니창에서 바꿀 수 있습니다**.
- `고유`: 계정마다 서로 다른 가상 비밀번호(서비스별 자동, 입력하지 않음)
- 입력한 값은 표시용이 아니라 **실제 모의 계정 생성·인증에 쓰입니다**. 기존 해시 방식(PBKDF2-HMAC-SHA256 + 계정별 salt)은 그대로이며 시각화를 위해 약화하지 않습니다.
- 판정은 그룹 이름이 아니라 값으로 합니다. 그래서 변경 전·후에 같은 `그룹 A` 라도 값이 다르면 결과가 달라지고, 다른 그룹에 같은 값을 넣으면 같은 비밀번호로 인증됩니다.

DB에는 평문 비밀번호 없이 `password_hash`와 `salt`만 저장되며, 로그인 로그에도 비밀번호는 기록하지 않습니다. 평문은 인증에 필요한 범위(모의 서버로 보내 해시할 때)에서만 쓰고 **실행 스냅샷·애니메이션 데이터·로그·오류 메시지에는 넣지 않습니다**. 교육용으로 보여 주는 해시는 서버가 실제 저장·검증한 값이며 상세창에서만 확인합니다.

## 기본 시나리오

| # | 변경 전 | 변경 후 | 유출 출처 | 12개 기준 결과 (검사 대상 11개, 접근 성공 전 → 후) |
|---|---|---|---|---|
| ① | 대부분 같은 비밀번호(A), 일부 다른 비밀번호·아이디, MFA 없음 | 비밀번호 유지 + 메일·학교·클라우드 MFA | 커뮤니티 | 7 → 5 |
| ② | 여러 서비스 A, 일부 B·C·고유 | 출처(쇼핑)를 **포함해** 모든 서비스 고유 비밀번호 | 쇼핑 | 6 → 0 |
| ③ | 대부분 같은 비밀번호(B), 메일만 MFA | 비밀번호 유지 + 모든 서비스 MFA | 커뮤니티 | 7 → 0 (8개는 MFA 단계, 3개는 아이디·비밀번호 단계에서 멈춤) |

표의 수치는 기본 설정 그대로일 때의 결과이며, 설정을 바꾸면 달라집니다. 예를 들어 ①에서 학교는 이미 다른 비밀번호(C)라 아이디·비밀번호 단계에서 멈추므로, MFA를 켜도 성공 수는 바뀌지 않습니다. 테스트는 수치나 "성공 수가 줄어든다"는 방향을 고정하지 않고, 계정마다 설정과 유출 정보를 대조한 기대 결과가 인증 결과와 같은지 확인합니다.

## 테스트

```powershell
python -m pytest -q
```

- 해시 저장(평문 미포함, salt), 프로필 분리, 없는 `service_id` 404, 로그에 비밀번호 미기록, 외부 호스트 요청 차단
- 결과 유형별 독립 테스트: 아이디 불일치, 비밀번호 불일치, MFA 차단, 접근 성공
- 시나리오 × 계정 수(4·12·20)에서 계정별 인증 결과 = 설정 대조 결과, 출처 제외 검사 대상 수
- 시나리오 생성(변경 전·후 `service_id` 대응, 계정 수 범위, 계정 수 조정 시 입력값 유지)
- 애니메이션 데이터(출처 분리, 멈춤 단계 = API 결과, 사유 판정, 불일치·요청 오류 처리, 변경 옵션 표시, 집계 합계, 평문 비밀번호 미포함)
