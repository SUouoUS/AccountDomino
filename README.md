# AccountDomino

비밀번호 재사용과 MFA 설정에 따라 크리덴셜 스터핑 피해가 어떻게 번지는지 보여주는 **로컬 전용 교육용 시뮬레이터**입니다.
한 서비스에서 자격증명이 유출되면, 같은 비밀번호를 쓰는 다른 서비스가 도미노처럼 뚫리는 과정을 설정 변경 전후로 비교합니다.

> ⚠️ 모든 계정·비밀번호는 가상 데이터입니다. 앱은 `127.0.0.1`의 모의 인증 서버에만 요청하며, 실제 외부 서비스나 실제 계정에는 절대 요청하지 않습니다.
> (`accountdomino/client.py`는 `localhost`/`127.0.0.1` 외의 주소를 거부합니다.)

## 구성

| 구성 요소 | 역할 |
|---|---|
| Streamlit (`app.py`) | 사용자 화면: ① 계정 설정 → ② 경로 시뮬레이션 (테마: `.streamlit/config.toml`) |
| FastAPI (`accountdomino/api.py`) | 모의 인증 서버. 하나의 서버에서 `service_id`로 `mail`(메일)·`shop`(쇼핑)·`community`(커뮤니티)·`school`(학교)을 구분 |
| SQLite (`data/accountdomino.db`) | 계정(해시), 실행 기록, 로그인 로그 저장 |

```
accountdomino/
  config.py      서비스 목록, 결과 상수, DB/API 경로
  security.py    PBKDF2-HMAC-SHA256 + 계정별 salt 해시
  db.py          스키마
  auth.py        핵심 인증 로직(판정·로그 기록)
  scenarios.py   비밀번호 그룹, 기본 시나리오 3개
  simulation.py  유출 자격증명, 설정 대조 판정, 결과 집계, 애니메이션 데이터
  animation.py   애니메이션 HTML 렌더링
  static/domino_animation.html  경로 애니메이션(SVG/JS, 외부 리소스 없음)
  api.py         FastAPI 앱
  client.py      localhost 전용 API 클라이언트
app.py           Streamlit 화면
scripts/init_db.py  DB 초기화 + 기본 시나리오 적재
tests/           핵심 인증 로직·API·시나리오 테스트
```

## 실행 방법

Python 3.11 이상이 필요합니다.

```powershell
python -m venv .venv
.venv\Scripts\activate            # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt

python scripts/init_db.py         # DB 초기화 (옵션: --scenario s1|s2|s3)

# 터미널 1: 모의 인증 서버
uvicorn accountdomino.api:app --host 127.0.0.1 --port 8000

# 터미널 2: 사용자 화면 (http://localhost:8501)
streamlit run app.py
```

API 문서는 서버 실행 후 http://127.0.0.1:8000/docs 에서 확인할 수 있습니다.

## 사용 흐름

앱은 두 화면으로 구성됩니다. 화면을 오가도 입력값(시나리오, 계정 설정, 유출 출처)은 유지됩니다.

**① 계정 설정**
1. 기본 시나리오를 고르고 **시나리오 불러오기** (또는 직접 설정)
2. **변경 전 / 변경 후** 표에서 서비스별 아이디, 비밀번호 그룹, MFA 여부를 편집
3. 유출 출처 서비스를 선택 — **변경 전** 설정의 출처 계정에서 유출 정보를 한 번만 만들고, 변경 전·후 모두 같은 정보로 시도
4. **시뮬레이션 시작** → 두 설정에서 각각 4개 서비스에 모의 로그인한 뒤 ② 화면으로 이동

**② 시뮬레이션**
- 계정 소유자에서 서비스별 경로가 갈라지고, 각 경로는 `서비스명 → 아이디·비밀번호 확인 → MFA → 접근 결과` 순서입니다.
- 유출 정보로 시도하는 로그인(검은 점)이 경로를 따라 이동하며, 각 확인 단계 앞에서 잠시 멈춰 "확인 중"을 보여 준 뒤 통과하거나 멈춥니다. 한 설정의 재생은 약 11초이며, 끝나면 최종 결과가 그대로 유지됩니다.
- 차단 지점은 초록색 `차단`과 짧은 이유, 비인가 접근은 빨간색 `비인가 접근 성공`으로 표시합니다(색과 문구로 함께 구분).
- 보기: `변경 전` / `변경 후` / `전후 비교`(기본, 변경 전 재생 후 변경 후 재생). 변경 후 보기에서는 바뀐 옵션(예: `MFA 꺼짐→켜짐`, `비밀번호 그룹 A→고유`)을 경로 위에 표시합니다. 재생 · 일시정지 · 다시 재생을 지원합니다.
- 재생이 끝나면 실제 결과를 설명하는 한 문장만 표시합니다. 가정: 로그인 시도자에게는 추가 인증 수단이 없습니다.
- **설정으로 돌아가기**로 ① 화면에 돌아가 값을 바꾸고 다시 시작할 수 있습니다.

상세 결과표와 로그는 사용자 화면에 보이지 않지만, 검증용으로 DB(`runs`, `login_logs`)에 계속 기록되며 API `GET /logs`, `GET /runs/{run_id}/logs`로 확인할 수 있습니다.

결과를 오해 없이 보여주기 위한 규칙:

- **멈춤 위치는 모의 인증 API 결과만으로** 정합니다.
- **이유는 따로 판정**합니다. 실행 당시 설정과 유출 정보를 대조한 기대 결과가 API 결과와 같을 때만 원인(`유출된 아이디와 다름`, `유출된 비밀번호와 다름`, `추가 인증 수단 없음`)을 표시하고, 다르면 `설정과 인증 결과가 일치하지 않음`으로 표시합니다.
- 네트워크 오류나 알 수 없는 응답은 `요청 오류`로 표시하며, 성공·차단 집계에서 제외합니다.
- 애니메이션은 **시작 시점의 설정·결과 스냅샷**만 사용합니다.

화면 폭이 약 1280px 이상일 때 노드 글자가 16~18px로 표시되며, 더 좁은 화면에서는 경로 그림 전체가 비례해 축소됩니다.

### 판정 규칙

| 조건 | 결과 |
|---|---|
| 아이디가 없거나 비밀번호 해시가 다름 | `비밀번호 불일치` (계정 존재 여부는 노출하지 않음) |
| 비밀번호는 맞지만 MFA 적용 | `MFA 차단` (로그인 시도자는 추가 인증 수단이 없다고 가정) |
| 비밀번호가 맞고 MFA 미적용 | `접근 성공` |

차단 계정 수 = `비밀번호 불일치` + `MFA 차단`. 유출 출처 서비스도 로그인 대상에 포함됩니다.

### 비밀번호 재사용 그룹

- `A`~`D`: 같은 그룹이면 같은 가상 비밀번호를 재사용 (예: 그룹 A = `Domino-A!2024`)
- `고유`: 서비스마다 다른 가상 비밀번호

DB에는 평문 비밀번호 없이 `password_hash`와 `salt`만 저장되며, 로그인 로그에도 비밀번호는 기록하지 않습니다.

## 기본 시나리오

| # | 변경 전 | 변경 후 | 유출 출처 | 접근 성공 (전 → 후) |
|---|---|---|---|---|
| ① | 전 서비스 같은 비밀번호, MFA 없음 | 메일·학교에 MFA 적용 | 커뮤니티 | 4 → 2 |
| ② | 메일·쇼핑·학교 = A, 커뮤니티 = B | 출처(쇼핑)를 **포함해** 모든 서비스 고유 비밀번호 | 쇼핑 | 3 → 0 |
| ③ | 전 서비스 같은 비밀번호, 메일만 MFA | 비밀번호 유지 + 전 서비스 MFA | 커뮤니티 | 3 → 0 (4개 모두 MFA 단계에서 멈춤) |

표의 수치는 기본 설정에서의 결과입니다. 예를 들어 ②에서 출처 계정(쇼핑)만 기존 비밀번호를 유지하면, 그 계정은 같은 유출 정보로 여전히 접근됩니다. 테스트는 수치를 고정하지 않고 계정별 설정과 유출 정보를 대조해 기대 결과를 계산합니다.

## 주요 API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/services` | 서비스 목록 |
| GET/PUT | `/profiles/{before\|after}/accounts` | 계정 설정 조회/저장 (서버에서 해시) |
| POST | `/scenarios/{id}/load` | 기본 시나리오를 변경 전/후에 적재 |
| POST | `/runs` | 시뮬레이션 실행 기록 생성 |
| POST | `/services/{service_id}/login` | 모의 로그인 (결과 반환 + 로그 저장) |
| GET | `/runs/{run_id}/logs`, `/logs` | 로그인 로그 조회 |

## 테스트

```powershell
python -m pytest -q
```

해시 저장(평문 미포함, salt), 세 가지 판정 결과, 프로필 분리, 없는 `service_id` 404, 로그에 비밀번호 미기록, 외부 호스트 요청 차단, 기본 시나리오의 설정 대조 판정, 애니메이션 데이터(멈춤 단계=API 결과, 사유 판정, 불일치·요청 오류 처리, 변경 옵션 표시, 평문 비밀번호 미포함)를 검증합니다.
테스트는 임시 DB(`ACCOUNTDOMINO_DB` 환경변수)를 사용하므로 실제 데이터에 영향을 주지 않습니다.
